What does the generator actually produce?

Speaker script

Take this equation as a simple example. The generator identifies the concepts involved, such as distribution and inverse operations, then writes a main question and an easier version for each planned step. For distribution, the main question might ask the student to expand two times x plus three. The retry could use smaller numbers, like two times x plus one. Each question also needs options, an answer key, a hint and an explanation. That gives the checker specific things to inspect. Getting the JSON format right is useful, but it doesn't tell us whether the maths is right.

The checker gets the problem, not just the answer key.

Speaker script

The checker isn't just asked whether the output looks good. It gets the original problem and the generated material, then uses a checklist. For the breakdown, it looks for missing or unnecessary prerequisites. For the probes, it checks the answer key, options, concept match, explanation, hint and retry difficulty. Here's an example: if the generator marks two x plus three as the expansion of two times x plus three, the checker should flag the answer key because the correct result is two x plus six. That's the behaviour we want to measure, not a result we're claiming. It returns findings; it doesn't automatically rewrite the question.

A second AI opinion still needs a reference.

Speaker script

So why not just trust the checker? Research on AI judges gives us a reason to be careful. Thakur and colleagues found differences between model judgements and human ratings, including leniency and sensitivity to the prompt. Yamauchi and colleagues found that clear evaluation criteria mattered. For us, that means asking specific questions like 'is the marked answer correct?' rather than 'is this a good question?' It also means comparing the checker with answers reviewed by a person. Using a second call is another chance to catch a mistake, but using the same provider means it can also repeat the first call's mistake.

Can it catch a mistake we already know is there?

Speaker script

Here's the test in plain terms. Start with a question and answer that a maths educator has checked. Make a copy and deliberately put one mistake in it, like marking the wrong answer. Send both versions to the checker. We want it to flag the changed version and leave the correct version alone. We have built a small runner with two unchanged examples and eight deliberately changed examples, all based on one equation. We haven't run it against the live model, and the examples still need independent educator review. Even a good result on that small set would only be a first check. We'd need more topics and real tutor feedback before making a broader reliability claim.

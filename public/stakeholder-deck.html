EEF guidance recommends formative assessment as a foundation for effective feedback. Our probes are intended to supply that evidence, not replace high-quality instruction.

EEF (2021), Teacher Feedback to Improve Pupil Learning, Recommendation 103 / 12
This is the strongest direct educational rationale in the deck. The guidance is about classroom feedback, not a trial of our AI system or an Ontario tutoring queue. We are translating a principle into a prototype; transfer to this setting still requires evaluation.

Worked illustration / Synthetic responses

A targeted probe can reveal which part of a problem needs attention.

Original question

2(x + 3) = 14

Distribute → balance → divide

Reference solution: 2x + 6 = 14 → 2x = 8 → x = 4.

Probe: expand 2(x + 3)

A. 2x + 3 / selected
B. 2x + 6 / correct

Possible gap: multiplying the constant inside the brackets.

Project-authored example, not an actual student or live-model accuracy result04 / 12
The distractor is informative because it preserves the x term but fails to multiply the constant. That is a hypothesis about the response, not a diagnosis. Ask the learner to explain their choice. Other explanations include a slip, misreading, or guessing. The full app has four options; this slide shows the selected option and key only to keep the story clear.

Validation architecture

Use three checks, with independently checked mathematics as the anchor.

1 / Contract checks

Required fields, four choices, stored keys, and answer flow.

Detect malformed or inconsistent artifacts.

2 / AI reviewer

Review breakdown, options, explanations, and hints.

Implemented; opt-in. Accuracy not yet benchmarked.

3 / Reference + tutor

Solve independently, then review diagnostic relevance.

Evaluate missed errors as well as successful detections.

Confidence currently reflects heuristic coverage/timing. It is not a calibrated probability that the brief is correct.

No-issue AI review ≠ a verified answer / tutor confirmation remains essential07 / 12
The reviewer is a second call through the same provider, not necessarily a different model. To test it, include clean controls and known wrong keys, duplicate valid options, off-topic probes, and revealing hints. Measure detection and false flags. No live benchmark was executed in this session because no API credential is available.

Then: supervised pilot

Research justifies the experiment. Results must justify the rollout.

Ask: a math reviewer, participating tutors, and an agreed evaluation protocol11 / 12
Proposed gate: no unresolved answer-key errors in the reviewed sample, documented reviewer failure rates, and an agreed timing/comprehension criterion. These gates have not been achieved. Keep sessions/history, persistent profiles, authentication, and public deployment separate. Real learner data requires privacy, consent, and access-control work beyond this local prototype.
